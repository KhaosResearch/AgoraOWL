Abstract

Lightweight ontology for data spaces. Version 1.3.0 makes the core OWL 2 DL conformant, adds the disjointness and functional-property axioms that let a reasoner actually detect a modelling error, moves every axiom over third-party properties into an optional alignment module so merging AgoraOWL with DCAT, DCMI, ODRL or FOAF no longer changes their meaning, and closes the matchmaking specification with an explicit enforcement policy for constraints that cannot be evaluated. The modeling follows alignment with DCAT-AP-ES, the CRED model, and the IDSA Information Model to ensure cross-domain semantic interoperability.

Introduction back to ToC

AgoraOWL provides a compact yet expressive vocabulary to describe the operational semantics of data spaces. Version 1.3.0 is about making the validation layers actually validate, and making the ontology safe to merge. ### What's new in v1.3.0 - **OWL 2 DL conformance**: the core passes `robot validate-profile --profile DL` with no violations. It had 13, so strict OWL tooling either rejected it or silently dropped axioms. - **The OWL layer can now fail**: disjointness across the structural layers plus ten functional properties. Up to v1.2.1 there was not a single disjointness or functional axiom, so no reasoner could detect any modelling error at all. - **Optional alignment module (`alignment.ttl`)**: `rdfs:domain`/`rdfs:range` axioms over third-party properties leave the core. Eight of them contradicted their source vocabulary and were corrected. - **Executable matchmaking**: `:constraintEnforcement` (`:Mandatory`/`:Preferred`), `:requiresFormat`, `:requiresMediaType` and `:UnitIntervalMetric` close the gaps that left the outcome of a match undefined. - **EDC connector profile**: shapes validating the `dcat:Dataset` an Eclipse EDC connector publishes over DSP, which is not the same graph as the Management API asset. ### Decoupled Architecture 1. **DataSpecification (Semantics)**: Atomic reusable unit (FOI + Observable Property). 2. **FieldMapping (Bridge)**: Links semantics to physical fields, units, and quality metrics. 3. **Profiles (Requirements)**: `InputProfile` and `OutputProfile` define the semantic requirements/offers of Apps.

AgoraOWL: Description back to ToC

AgoraOWL aims to achieve sectoral semantic interoperability within data spaces by decoupling physical data distributions from their semantic specifications. Version 1.3.0 follows strategic alignment with DCAT-AP-ES, the CRED model, and the IDSA Information Model; it is OWL 2 DL conformant, keeps third-party alignment in a separate opt-in module, and specifies matchmaking precisely enough to be executable. For example, a DataApp requiring 'Soil Moisture' in percentage can automatically discover and consume a Dataset whose distribution (CSV/Parquet) is semantically mapped to that specification through FieldMappings.
